# 對照實驗與失敗分析（S6）

## 實驗設定

- **資料**：Elden Ring wiki 爬下來的結構化 CSV，清理後建成知識圖譜（Neo4j，3,860 個節點、6,592 條邊）與向量索引（3,649 篇文件，bge-large-en-v1.5）。
- **題庫**：106 題、7 種題型，標準答案與來源列由我自己撰寫（`eval/questions.jsonl`）。
- **生成器**：A、B、C 三組**都用同一個本機模型 Qwen3.5-4B（Q8_0，llama.cpp，temperature 0）**，只有檢索方式不同。
- **判定**：AI 判定（Claude），先用關鍵字重疊做初篩，需要複查的 31 題（A 組）與 C 組的非正確題目逐題對照標準答案複核。**不是人工判定**，方法與限制見 `docs/eval-methodology.md`。
- **分數**：correct = 1、partial = 0.5、wrong = 0。

| 組別 | 說明 | 工具 |
|---|---|---|
| A | 純向量：top-5 段落直接放進 prompt | 無工具，一次檢索 |
| B | 只用圖工具 | `get_entity`、`get_neighbors`、`find_path`、`filter_by_attribute`，LLM 自己選 |
| C | 向量＋圖 | 上面四個圖工具＋`vector_search`，LLM 自己選 |

B、C 都有實體連結提示（問題中偵測到的實體名稱放進使用者訊息）。`--no-hint` 的對照在下面單獨列出。

## 結果解讀

**1. 多跳題：圖組明顯勝出（生成器一致）**
- 18 題中，A 組答對 14 題，B、C 全對。差距 22.2 個百分點（4 題）。
- 原因：多跳題需要先找到一個實體、再沿關係走到下一個（例如「Volcano Manor 主線 boss 掉的紀念品能換什麼」）。向量檢索常撈不到第二跳的段落，圖工具則直接沿邊查。
- 這是在同一個生成器（Qwen）下的比較，之前「圖多 16.7 個百分點」的說法因生成器不同不成立，本表才是正確的對照。

**2. 錯誤前提題：純向量勝出**
- A 組 0.750，B 組 0.167，C 組 0.333。
- 原因：圖工具查到了正確的關係資料，但模型只回答查到的東西，不回頭比對題目宣稱的前提。A 組則是撈不到確認矛盾的段落時，傾向老實拒答，剛好貼近答案。
- 修正 prompt 後（見失敗分析），在這 6 題上 B 提升到 0.583、C 到 0.667，但仍低於 A 組。**這是圖組目前明確的弱點，不是只有提示的問題。**

**3. 其他題型**：單跳題、數值題、關係題三組大致持平，差異都在 1 題以內，不足以下結論。

**4. 提示的影響**：無提示時 B 組整體由 0.943 降到 0.915，C 組降到 0.934（見下節）。**提示是 B 組表現的一部分來源，不能全部歸功於圖本身。**

## `--no-hint` 對照（摘要）

拿掉實體連結提示，B、C 整體分別由 0.943 降到 0.915、0.934（有提示與無提示都是 106 題、各跑一次）。

- **最乾淨的例子是 q08（Ensha 同名雙重身分）**：有提示時兩組都答對，無提示時兩組都斷言「沒有角色同時是 NPC 又是 boss」。這說明**實體連結對圖組是必要的，尤其是名字不完全一致的情況**。
- B 組掉 2.8 個百分點，C 組只掉 0.9 個百分點：向量檢索在 C 組多一個備援，減少了提示缺失的影響。
- 完整數字與逐題分析見 `docs/agent.md`。

## 限制

1. **B、C 主表是修正 prompt 之前的結果**。錯誤前提的 prompt 修正只在 6 題錯誤前提題＋q08 上測過，多跳題沒有重跑。修正後的 B、C 完整 106 題還沒跑。
2. **每組只跑一次**，沒有變異估計。多跳題 18 題，每題約 5.6 個百分點；錯誤前提 6 題，每題約 16.7 個百分點。
3. **判定是 AI（Claude）完成**，且判定者知道每題屬於哪一組，沒有盲評。人工抽樣複核還沒做。
4. **題庫由我撰寫**，單跳題由模板產生、題目內含實體名稱，對向量檢索偏容易，對圖組偏有利（多跳題也是我設計的）。
5. **圖的資料還有缺口**：剩 35 條 Boss↔地點的單邊關係（見 `docs/graph-schema.md`），235 個 stub 節點，NPC 與 Boss 之間沒有 `SAME_AS`；向量索引裡同名 Item 還有重複文件（見 `docs/note.md`）。
6. **Qwen3.5-4B 是 4B 模型**。Claude Haiku 4.5 在相同工具下工具呼叫明顯更有效率（Ensha 題 2 次呼叫、0 錯誤，Qwen 為 6 次、2 錯誤），所以結論限定在這個生成器的範圍。
7. **A 組的 recall 與 B、C 的覆蓋率定義不同**，表中兩者都是參考，不能直接比。

## 結論

在這個遊戲資料庫、這份自撰題庫、同一個 4B 生成器下：

- 圖工具在**多跳題**上明顯優於純向量（14/18 → 18/18），這是本實驗最穩定的結果。
- 圖工具在**錯誤前提題**上明顯較弱，而且修正 prompt 後只能部分改善。這說明「能查到資料」不等於「能推理出前提不成立」。
- 整體正確率三組相同（A 0.929、B 0.943、C 0.943），**差異不在整體分數，而在題型的分布**。
